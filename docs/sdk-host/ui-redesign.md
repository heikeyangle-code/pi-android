# UI 重做方案（SDK 版）

> 范围：`ui-design.md` 管的是「扩展的 UI 调用怎么画」；本页管的是**整个 App 的界面在 SDK 之后该长什么样**。
> 决策已定，实现按此做。**现有界面为 RPC 的阉割能力而生，不受保护，该推翻就推翻。**
> 没写代码，没编译，没上机。每一条都标了它依赖的宿主命令 —— 命令都已实现并有测试（`docs/sdk-host/capabilities.md`）。

## 0. 设计立场（按优先级）

1. **宿主持有真相，界面只投影。** 模型、思考等级、用量、队列、是否在流式…… 全部来自宿主推的 `state`
   （`HostStateStore`）。界面里不允许出现「自己攒一份状态再去对账」的代码；这是现在 `PiSessionViewModel`
   6000 行里最大的一块债。
2. **能力驱动，不是版本驱动。** 入口亮不亮看 `host.hello.capabilities` 和命令表，不看「是不是新版」。
   pi 升级多出来的能力，在 `sdk.call` 通用口上先能用，值得了再长成具名入口。
3. **一手机一手：单手可达、一屏一件事。** 底栏已经拆掉（既有裁决）；我继续这条线：
   顶栏只放 **返回 + 标题 + 一个「⋯」**，所有次要动作进 ⋯；高频动作（发送、停止、切模型）在拇指区。
4. **长任务永远可见、可取消、可恢复。** 装包、登录、压缩、MCP 检测、子代理 —— 任何会超过 2 秒的事，
   都有进度行 + 取消；被杀进程后重开能看到「刚才在做什么」。
5. **不替用户转录 pi 的规则。** 资源开关、设置落盘、MCP 配置格式 —— 一律让 pi 自己写（宿主命令已是官方函数），
   界面不再拥有任何 `+/-/!` 规则、键路径表、校验器的副本。
6. **原生优先，等宽兜底。** 扩展给的是数据 → 原生控件；给的是终端组件 → 等宽「表面」（`ui-design.md` §1）；
   想原生 → PAUI。

## 1. 导航：三处目的地，一条主线

保持既有裁决（对话 / 工作区 / 设置，无底栏），但**重新分工**：

| 目的地 | 现在 | 重做后 |
|---|---|---|
| 对话 | 聊天 + 一堆浮层 | 聊天 + **一个**底部抽屉「会话面板」（§2.4）承载树 / 分叉 / 队列 / 子代理 / 上下文用量 |
| 工作区 | 文件、资源、终端残留 | 文件 + **资源**（扩展/技能/模板/主题，§4）+ **MCP**（§5）+ 包（§4）。这些全是「这个项目带着什么」 |
| 设置 | 一个 4000 行的手抄注册表 | **供应商与登录**（§3）+ 设置（§6）+ 诊断。设置页不再有自己的 JSON 层 |

## 2. 对话页

### 2.1 顶栏
标题 = 会话名（`state.sessionName`，点一下改名 → `session.name`）。副标题一行小字：`模型 · 思考等级 · 用量%`
（全来自 `state`；用量 = `contextUsage`）。**这一行就是「状态条」**，取代现在散在各处的小徽标。
长按副标题 = 打开模型选择器。

### 2.2 输入区
- 一个输入框 + 一个主按钮。主按钮三态：**发送**（空闲）/ **停止**（流式中且输入为空）/ **排队**（流式中且有输入，
  `chat.send` 自己决定 steer 还是 followUp，界面只说「排队」）。
- 左侧一个 `+`：附件、`/` 命令、`@` 文件。命令面板来自 `catalog.commands`，**按 source 分组**
  （内置 / 扩展 / 技能 / 模板），每条带来源徽标（`sourceInfo`）。技能与模板调用不产生用户气泡（与 pi 一致）。
- 流式中输入框上方出现**队列条**：显示 `pendingMessageCount`，点开列出排队内容，可「全部取回」
  （`session.clearQueue` → 文本回填输入框）。

### 2.3 消息流（`Transcript.kt` 的去留）
`Transcript.kt`（2771 行）是**事件→行**的归约器，建立在 RPC 事件之上。SDK 的 `agent` 事件与它同形
（宿主原样转发，仅 `message_update` 去掉 `partial`），所以**归约逻辑可以留**，但要做三件事：
1. 输入端换成 `HostSignal`（已有）；`epoch` 变化 = 整条流重放（会话被替换），归约器必须 `reset()`。
2. 行类型**开放**（`dual-engine.md` §2.4）：通用行 + 带 `kind` 的专属行 + 未知兜底卡，不再是封闭枚举。
3. 扩展注册的消息渲染器（`render.message`）产出的行走「表面」样式，不套气泡。

工具卡：一行摘要（工具名 + 关键参数 + 状态点）→ 点开看详情；**运行中的工具有计时**；失败默认展开。
bash 工具输出等宽、可折叠到 N 行；超长输出显示「已截断 · 查看完整」（`session.bash` 的 `truncated` 标志）。

### 2.4 会话面板（底部抽屉，上滑或「⋯」）
一个抽屉，**分段**切换，取代现在的「会话浮层 + 树浮层 + 分叉弹窗」三套：
- **树**：`session.tree`，当前叶子高亮；点节点 = `session.navigate`（树导航），弹窗问「是否摘要被离开的分支」
  （`summarize` / `customInstructions` / `label`）。**这是官方 `/tree`，不再靠 `pi-android-bridge` 绕路。**
- **分叉**：`session.forkMessages` → 点哪条用户消息就从那里 `session.fork`；「克隆当前」= `session.clone`。
- **上下文**：`contextUsage` 环形图 + `session.stats` 数字（输入/输出/缓存/成本）；按钮「压缩」
  （`session.compact`，带可选指示语；压缩中显示进度并可 `session.abort`）；自动压缩开关。
- **子代理**（装了 pi-subagents 才出现，`subagents.rpc` 能力）：见 §7。

### 2.5 模型与思考
选择器是一张底部表：供应商分组 → 模型行（名称、上下文窗口、是否推理、**认证状态点**：绿=已配置 / 灰=未配置，
点灰色直接去登录，§3）。思考等级是同一张表底部的一排分段按钮，**只显示 `thinking.levels` 返回的等级**
（模型不支持推理时整排隐藏）。「循环切换」手势保留（`model.cycle` / `thinking.cycle`）。

## 3. 供应商与登录（重做，原 `ModelProviderScreen` 2949 行 + `SubscriptionLogin` 582 行）

数据源：`auth.providers`（每个供应商的认证方式、是否已配置、状态）、`auth.credentials`。

- 一个列表：**已配置**在上，**可添加**在下；每行 = 名称 + 认证方式徽标（API Key / 订阅登录）+ 状态点。
- 点行 → 详情页：
  - **API Key**：一个输入框（粘贴友好）→ `auth.setApiKey`（写盘）；已有则显示「已配置」+「更换」「移除」（`auth.removeApiKey`）。
  - **订阅登录（OAuth）**：一个大按钮「用 XX 登录」→ `auth.login`。流程由事件驱动：
    - `auth.event{auth_url}` → 弹出「在浏览器打开」按钮 + 说明文字；
    - `req auth.prompt{type:"manual_code"}` → 一个输入框「如果浏览器没能回到本机，把地址栏里的网址贴在这里」；
    - `auth.event{device_code}` → 大字显示设备码 + 复制 + 打开验证页；
    - `auth.event{progress/info}` → 一行进度；**始终有「取消」**（`auth.cancel`）。
- **导入模型 / 自定义模型**：模型定义文件 `models.json` 仍是 pi 的格式，导入页可以保留，但「保存后让 pi 重新加载」
  改为 `session.reload`（不再重启进程）；保存后立即 `auth.refreshModels`。**这一页是少数不用推翻的。**
- 不再有「订阅登录起子进程」那条路（`pi-oauth.mjs` 删除）。

## 4. 工作区：资源与包（重做，原 `ResourceManagerPanel` / `PiPackagesScreen`）

数据源：`resources.list`、`packages.list`、`packages.updates`。

- 顶部分段：**全局 / 本项目**（项目未信任时「本项目」灰掉并给一句话 + 「信任」按钮 → `project.trust`）。
- 下面按**类型**分节（扩展 / 技能 / 提示模板 / 主题），每节一组开关行：名称、来源（包名/本地/内置）、开关。
  项目视图的开关是**三态**（继承 / 开 / 关），与 `pi config` 一致；继承的行用灰字标「继承自全局」。
  点开关 → `resources.toggle`；返回的是写完后的整份清单，**界面直接替换**，不再本地拼。
- **包**是一个子页：已装列表（来源、作用域、是否被过滤、`installedPath`）+ 「检查更新」（`packages.updates`）
  + 「安装」输入框（npm 名 / git / 本地路径）。安装/卸载/更新都是长任务：
  一行进度（`packages.progress`）+ 取消不可用时明说（官方包管理器没有取消）+ 失败原文展示。
- **装完不自动重载**：底部出现一条粘性提示「新资源需要重新加载才能进入当前会话 [重新加载]」→ `session.reload`。
  重载是进程内的，不会丢对话；这一条取代旧的「需要重启 pi」整套文案与确认流程。

## 5. 工作区：MCP（重做，原 `McpServersScreen` 989 行）

数据源：`mcp.list`（会真连每个服务器，慢：显示骨架屏 + 每台服务器各自出结果的动画不可行，因为是一次性返回，
所以用**整页进度 + 取消**，并且结果缓存到下次手动刷新）。

- 服务器卡：名称、传输（stdio/HTTP）、状态点（connected / needs-auth / failed / disabled）、工具数、
  暴露方式徽标（codemode / deferred / direct / hidden）。展开看工具名与错误原文。
- 动作：启停开关（`mcp.update{enabled}`）、暴露方式选择（`mcp.update{exposure}`，选项旁一句话解释各自含义）、
  登录（`mcp.login`）、退出登录（`mcp.logout`）、删除（`mcp.remove`）。
- **添加**：两个入口卡——「命令行服务器」（命令 + 参数 + 环境变量）/「网址服务器」（URL + 请求头 + OAuth 选项）。
  表单直接对应 `mcp.add` 的字段；校验错误是官方原文。
- **OAuth 登录**（`mcp.login`）：`mcp.auth` 事件给授权链接 → 「在浏览器打开」；同时显示贴回框
  （`mcp.redirect`）。手机上浏览器与引擎之间的回调**可能到不了本机**，这是贴回框存在的原因，必须一直可见，
  不是「失败后才出现」。
- 改完启停/新增后提示「重新加载后进入当前会话」（同 §4）。

## 6. 设置（重做，原手抄注册表 ~4000 行）

数据源：`settings.get`（有效 / 全局 / 项目 + 是否信任）、`settings.set{method,params}`。

- **设置项的元数据（标题、分组、控件类型、取值范围）仍然需要有**——SDK 只有 TS 类型，没有运行时 schema，
  所以 `PiSettingsRegistry` 作为「界面元数据」保留，但**瘦身**：只留 标题/分组/控件/选项/对应的 `setXxx` 方法名。
- **删掉**：自己读写 `settings.json` 的 `PiSettingsJson`/`PiSettingsInMemory`/`PiSettingsStore`/`PiFileWatch`，
  以及与 SDK 重复的 `PiSettingsValidation`（**先验证 SDK 的 setter 对同一批非法输入确实拒绝**再删；
  没验证前不删，见 §9 自审 #4）。
- 每个设置行：当前有效值 + 来源徽标（默认 / 全局 / 项目）。改 = `settings.set` → 收到整份新设置 → 替换。
  失败是 SDK 的原话。「项目」层的行在未信任时灰掉。
- `settings.changed` 事件 = 别处（比如 CLI 手改文件后）变了：重取 `settings.get`。

## 7. 子代理（pi-subagents，能力 `subagents.rpc`）

数据源：`subagent.rpc`（`status`/`spawn`/`steer`/`interrupt`/`stop`/`resume`/`cost`）+ `bus.subscribe`
（`jobs-changed` 等事件）。

- 会话面板里一个分段「子代理」：任务列表，每项 = 名称、状态点、已用时、成本；点开 = 该子代理的**实时输出**
  （事件流里按 jobId 过滤）、「引导」输入框（`steer`）、「中断」「停止」「恢复」。
- 主对话里子代理产生的工具卡带 `↳ 子代理名` 前缀，点击跳到该子代理视图。
- **没装扩展时整个分段不出现**（不是灰着）。

## 8. 启动、错误与恢复

- 启动三态：**拉起宿主**（秒级，`host.ready`）→ **加载 SDK**（`session.open` 在跑，显示步骤文字）→ **就绪**。
  手机上第二步最慢，**不许是转圈**：显示「正在加载 pi 引擎…（首次较慢）」并有计时。真实耗时没测过，不要在界面里承诺数字。
- 失败三类，各有自己的卡片、各有明确动作：宿主起不来（stderr 尾部 + 「换运行时重试」，proot ↔ proroot）/
  `session.open` 失败（`error.code` + 原文）/ 运行中宿主退出（「引擎已退出」+ 「重新打开会话」，
  走 `session.open{session:{file}}` 恢复**文件里已有的**内容；**进行中那一轮丢失**，要明说）。
- 项目未信任：`project.trust.required` → 一张卡（说明会加载哪些项目资源）+「信任并重载 / 仅本次不信任」。

## 9. 自审（我对这份方案的挑刺）

1. **用户可见的「重新加载」会不会太多？** §4/§5/§6 都有。风险：用户装了三个包，被提示三次。
   解法：提示条是**粘性且合并**的（一条，计数 +1），不是每次弹窗。已写入 §4，其他页同理。
2. **会话面板塞了四个分段（树/分叉/上下文/子代理），手机上会不会拥挤？** 会。折中：分段是横向滚动 chip，
   「子代理」在未装时隐藏；树与分叉合并为一个「历史」分段的可能值得评估——**这条需要真机上看**，我不拍板。
3. **MCP 检测慢且不可增量。** `mcp.list` 一次性返回，界面只能整页进度。若真机上耗时不可接受，
   需要给宿主加「逐个服务器返回」的事件版（宿主侧的小改动，`mcp.list` 内部本来就是 `Promise.all`，
   拆成逐个 emit 很容易）。**先不做，等真机数据。**
4. **「删掉 `PiSettingsValidation`」是未验证的建议。** SDK 的 setter 多数只赋值不校验（我只测了两个）。
   在验证前保留，否则会放行非法值写进 settings.json。
5. **订阅登录的「手动贴回」只有 OpenAI ChatGPT 那条路我在源码里确认过**（`manual_code`）。
   其他 OAuth 供应商是否都提供，没有逐个确认；界面按 prompt 的 `type` 渲染，不假设。
6. **手机上 OAuth 回调服务器（127.0.0.1:1455 等）在 proot / proroot 下能否被手机浏览器访问，未验证。**
   这是贴回框必须常驻的依据，也是真机清单（`runtimes.md`）要加的一项。
7. **`Transcript.kt` 留还是重写？** 我选留（§2.3），理由是事件同形、2771 行里大部分是渲染细节而非协议。
   代价是它里面仍有 RPC 时代的命名与假设；步骤 8 清理时再逐段审。这是保守选择，不是最优选择。
8. **没有设计的东西**：平板/横屏布局、无障碍（TalkBack 对「表面」的朗读）、深浅色下 ANSI 调色板的对比度验收。
   这三项必须在实现前补，否则会返工。

## 10. 落地顺序（每步可独立合并）

1. 对话页接 `state`：状态条、主按钮三态、队列条（依赖步骤 3）。
2. 供应商与登录页（最独立，宿主命令齐全，先做能立刻删掉 `pi-oauth.mjs`）。
3. 资源 + 包页（删 `pi-resources.mjs`）。
4. MCP 页（删 `PiMcpCheck`）。
5. 会话面板（树/分叉/上下文）。
6. 设置页瘦身。
7. 子代理。
8. 表面 / PAUI（`ui-design.md`）。
