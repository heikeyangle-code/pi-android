上下文圆环按钮 + 它的详情

主目标：顶栏的读数行整行拿掉，那些读数一项不少地折进输入区末尾这枚圆按钮和它的详情里 —— 那是它们唯一的地方。 顶栏只留身份那一行（会话名 + 引擎状态），会话名是切换会话的唯一入口。
基准 360dp 屏、两边各 14dp → 可用 332dp；等宽 12sp 每字符 7.20dp、中文 12.0dp；阈值沿用 pi：>70 warning、>90 error。

三条必须先说清的事实

  • 百分比是估算，不是分词器计数：pi 给的是「最后一次真实 usage + 之后每条消息按 Math.ceil(字符数 ÷ 4) 估」之和（compaction.ts:270-274、estimateContextTokens:215-238）。详情里照实写。
  • 分类明细 pi 不提供：参照图里的「系统提示词 / 工具定义 / 对话消息」三项，pi 没有任何字段能给。它只有总数。所以不做那块，只在详情里写一行「分类明细 pi 不提供」。绝不猜三个数出来。
  • 压缩之后百分比会「没有」：agent-session.ts:3441-3445 在压缩后到下一次回复之前返回 {tokens:null, percent:null}，但 contextWindow 仍然有 —— 所以环画空轨道，详情里窗口照常显示。

6 · 命中率放哪儿（我的判断）

  • 只保留 pi 原生那一个：单独一行、标题写明「最后一条回复」，放在两个用量组之外，这样它不会被读成任一组的一部分。
  • 本轮不另算命中率：pi 的公式定义在最后一条消息上（footer.ts:95-98）；把同一公式套到本轮四件之和会得到另一个百分比，屏幕上就同时有两个含义相近的数 —— 那正是上次误读的成因；而且它是二次派生的量，不是 pi 给的字段。
