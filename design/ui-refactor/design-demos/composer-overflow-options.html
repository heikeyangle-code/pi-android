输入区多出来的那个 ⋮

键位行从左到右：`/` · 附件（纯图标 30dp）· ⋮（干活时再加 `插话`/`排队`），右侧是 `◐ 等级名` + 30dp 发送键。 `@`（提及文件）、`!`（跑命令）、`!!`（跑命令 · 不进上下文）、`清空`（清草稿）四项收进 ⋮ 菜单。 这样一来那一行结构上就装得下了 —— 不需要任何按宽度退让的阶梯。
测量基准：360dp 屏、键位行可用 310dp；等宽 12sp 7.20dp/字符、中文 14sp 14.0dp/12sp 12.0dp。

2 · ⋮ 按钮本身：三个候选

V1（推荐）· 与 `/` 同族：24×24 芯片 + 三点图标

/ ← 虚线 = 32×32 触控区（视觉仍是 24×24）
  • 尺寸 / 形状：24×24、圆角 6、底色 surf-highest #303036 —— 与 `/`、附件、`插话`、`排队` 完全同族；不新造一种按钮。
  • 图标：自绘三点而不是 M3 的 Icons.Filled.MoreVert：视口 24、三个实心圆 r=2、圆心 y = 6 / 12 / 18、颜色 currentColor（--text），渲染 16dp。理由是顶栏那个 ⋮ 用的是 M3 图标（视觉 17–18dp、笔画更细），而这一枚要和 24dp 的芯片同高——自绘能精确控三点的直径与间距，且与 v2 的单线图标族（18 视口、stroke 1.5）不冲突（实心点不是描边图形）。
  • 间距：与其它芯片一样，尾距 6dp；不单独加宽。左右各 6dp 的节奏感是这一行的语法。
  • 触控：视觉 24×24，可点区域 32×32（向外 4dp，行高 30 之内，上下各让 1dp）。与上下文圆环那枚的做法一致 —— 24dp 的视觉 + 32dp 的触控是这一行能给的极限（48dp 会把行高抬到 48，与「别占显示区域」冲突）。
  • 按下态：整块底色 surf-high（比常态暗一阶的表面阶），不用 M3 默认的 primary 涟漪（那会出现 accent 光晕，而 v2 的 accent 只给主操作）。

V2 · 独立圆形描边

24dp 圆 + 1px borderMuted

问题：这一行右侧已经有两个圆（上下文环、发送键），再来一个圆就成「三个圆」；而且它和左边的方角芯片不是一族。不采用。

V3 · 无底色纯图标

只有三点，没有承载面

最轻，但它看起来不像键位行的一员（旁边每个键都有底），按下态也没有承载面。不采用。

4 · 菜单项：四项怎么排

@提及文件插入文件路径
!跑命令进上下文
!!跑命令不进上下文
清空
  • 顺序：`@` 在最前（最常用），紧跟着 `!` 与 `!!` 相邻 —— 这一对的差别只在说明列（进上下文 / 不进上下文），挨着放才能一眼比出来；`清空` 是另一种动作（丢弃，不是插入），用 1px 分隔线隔开。
  • 为什么不写成两行：说明只有 4–6 个汉字，右对齐在同一行就够；两行会把菜单从 169dp 撑到 200dp 以上，也让「四个动作」读起来像四条说明。
  • `!` 与 `!!` 的区分：两行标签都叫「跑命令」，差别全部落在右侧说明上，用词直接抄 pi 的语义：! 「进上下文」、!! 「不进上下文」。不允许只写符号或只写「同前」。
  • 选中后的行为不变：`@` 把 `@` 插进草稿并唤出提及候选；`!` / `!!` 分别进 shell 面板（后者不带进上下文）；`清空` 清掉草稿。菜单只是入口，处理函数一个都不动。
  • 内容宽度核算：最宽的一项是「@ 提及文件 … 插入文件路径」= 12 + 24 + 10 + 56 + 8 + 72 + 12 = 194dp ✓ 240dp 容器里余 46dp；「!! 跑命令 … 不进上下文」= 12+24+10+42+60+12 = 160dp ✓。

5 · 菜单从哪冒出来、会不会被挡住

@提及文件插入文件路径
!跑命令进上下文
!!跑命令不进上下文
清空
输入消息，/ 选命令…
/ ◐中 ↑
  • 向上展开：锚点是 ⋮ 的左边缘，底边贴在按钮上方 8dp。理由：输入框在最底部，下方的空间属于键盘/底栏，向下展开一定被挡。
  • 不需要翻转：菜单总高 169dp，上方是转录区（通常几百 dp），在任何竖屏高度下都放得下；横屏极端情况仍按「向上、必要时上移到不被 AppBar 遮住」处理，不做向下翻转（翻译成实现：Popup 里按可用高度钳制 y 即可）。
  • 键盘：Compose 的 imePadding() 已经把整个 scaffold 顶到键盘上方，输入框始终在键盘之上，所以向上展开的菜单也一定在键盘之上 —— 这条不需要额外处理，但要写进验收：键盘弹出 + 菜单展开时，四项都要完整可见。
  • 底栏：菜单向上，不进入底栏区域；底栏在输入框之下，两者不重叠。
  • 右边缘：⋮ 在左边，240dp 菜单不会越界；若将来按钮靠右，规则是「右对齐锚点」，与屏幕内边界保持 14dp。
  • 不用 scrim：v2 的 0.32 scrim 只给 sheet / dialog；菜单是轻量浮层，靠 1px 边框与表面阶与背景分开，点外部即关。

6 · 无障碍

元素标签（talkback 读出来的）要求
⋮ 按钮（输入区）更多输入方式不能只给图标不给名字；与顶栏那个 ⋮ 的名字必须不同（顶栏保持 更多），否则读屏时两个「更多」分不清
@ 提及文件提及文件，插入文件路径文字标签 + 说明一起读；不允许只读符号
! 跑命令跑命令，进上下文同上
!! 跑命令跑命令，不进上下文这一对的可访问名必须不一样（默认从文字取，正好满足）
清空清空草稿标签写全，避免只读「清空」不知道清什么

规则一句话：能看见符号的地方，旁边一定有一句中文；能读出来的名字里，一定包含那句中文（说明列也带上）。

7 · 推荐

V1 的 ⋮（24×24、圆角 6、surf-highest、自绘三点、触控 32dp、尾距 6dp）＋ v2 自绘菜单（surf-high + 1px borderMuted + 圆角 10 + 零阴影 + 项高 40 + 右对齐说明）＋ 四项顺序 @ / ! / !! / ─── / 清空 ＋ 向上展开、锚点在按钮上方 8dp、必须走 Popup。

一句话理由：这一行有四件不常按的动作要安置，菜单是唯一能让它在 310dp 里永久装得下的办法（最宽态从 365.0dp 的超宽降到 256.6dp），而 ⋮ 与菜单只要完全沿用 v2 既有语言（同族芯片 + 1px 线 + 表面阶 + 圆角 10），既不用新造按钮，也不用再写一条退让阶梯。
