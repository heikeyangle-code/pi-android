# 03 · 导航结构裁决（四目的地 → 三目的地）

> 用户原话（本次会话）：「终端页直接放到设置里，不要单独那一页了。或者把那一页改成工作区相关的，方便以后加 SAF 选工作区。改成两栏，一栏终端，一栏工作区。或者说，你看着办吧 现有的四个导航，你觉得怎么设计比较好？按照设计规范。我也不知道」
> 结论：父代理裁决，写在这里，三版初稿都照此做（用户可在三版面前否决，否决即改）。

## 现状（代码事实，`00-screen-inventory.md` §1）

底部四个目的地：`会话` / `对话` / `工作区` / `设置`。其中：

- `对话` = 转录主战场（hero）。
- `会话` = 会话列表（选会话的地方）；选中后 `switchSession` 并跳到 `对话`。
- `工作区` = **整屏一个 PTY 终端**（用户已宣布终端不可用）。
- `设置` = 唯一的多级结构（12 分组 + 7 个 App 专属子页）。
- 会话树已经是**覆盖层**（不是第五个 tab）。

## 裁决：底部三个目的地

| 目的地 | 是什么 | 变化 |
|---|---|---|
| **对话** | 当前会话的转录（hero）。左上角 = 会话名，点它进入**会话列表覆盖层**（列表 ↔ 会话树 在同一层切换），新建会话也在这里 | 吸收原「会话」tab 的入口 |
| **工作区** | **项目现场**：当前 cwd、这个目录里的 `.pi` 资源（技能/提示词/扩展/主题/包）、git 改动、这次会话动过的文件。以后在这里加 SAF 选工作区 | 从「整屏终端」改为真正的项目面板 |
| **设置** | 全部设置 + **终端入口**（全屏终端页从设置进入，不再是底部目的地） | 新增「终端」入口行 |

**终端**：降格为「设置」里的一个入口行（与 设备 / 扩展 / 关于 同级），点进去是全屏终端页。
**两栏**：只在宽屏（≥600dp，横屏或平板）出现——左「项目现场」+ 右「终端」；竖屏手机上**不做两栏**（412dp 宽两栏 = 每栏约 25 个等宽字符，终端根本没法用）。

## 为什么（四条理由）

1. **每个 tab 必须是一个「地方」，会话列表是「选择器」不是地方。** pi 自己就是把会话树覆盖在转录上；桌面端的惯例也是 drawer/sheet。把「会话」和「对话」并排做两个 tab，等于同一件事给两个家，用户永远分不清哪个是「我现在在的地方」。
2. **少一个 tab = 更大的触达目标、更少误触。** 三个底部项在 412dp 宽下每个约 137dp 宽；四个只有 103dp。
3. **终端不该和「对话」平级。** 终端是兜底入口（用户已判定它不可用），把它放在底部导航里，等于给一个坏掉的东西最高的可见度；放进设置，它仍然可达但不占主位。
4. **工作区值得保留一个 tab，但内容要是项目现场**。pi 没有 workspace 概念——一切都是 cwd 派生的（会话按 cwd 分组、`.pi/` 资源按 cwd 找）。所以「工作区」= 当前 cwd 的真实现场，而不是一个终端；这也正好是以后 SAF 选工作区的落点。

## 补充裁决：冷启动默认「新会话」

用户原话：「每次进去都是默认新会话就行。需要历史对话，可以自己打开。其他 AI APP 不都是这样的吗？」

- **保持现状**：`app.sessions.resumeLast` 默认关，打开 App = 新会话；会话列表/会话树由用户自己从对话页左上角打开。
- 因此 `01-design-spec.md` 里「对话（hero）」这台屏画的是**一个已经进行中的会话**，但设计必须同时交代新会话的起点（空态 + 引导），因为那才是用户每次打开时看到的第一屏。

## 对三版初稿的要求

- 底部导航统一改成 **三项：对话 / 工作区 / 设置**。
- 五台屏仍然是：① 对话（hero）② **会话列表（覆盖层，从对话页左上角进入）** ③ 工作区（项目现场）④ 设置首页（含「终端」入口行）⑤ 设置的一个分组页。
- 三版的结构差异放在**版面/构图/层级/组件语言/母题**上，不放在导航项数量上（导航是产品裁决，不是风格选择）。
